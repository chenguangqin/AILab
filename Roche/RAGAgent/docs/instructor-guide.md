# 三天实验教案摘要

## 统一教学动作

每个实验都执行：

```text
运行AI产物 -> 观察失败 -> 形成诊断 -> 指挥Claude Code修改
           -> 运行测试/指标 -> 解释为什么可信
```

不要让学员直接复制讲师实现。评分重点是能否解释修改和验证证据。

## 第一天

### E0

教师先展示知识库构建、在线查询和评估三条链路。学员运行Baseline，在Langfuse中定位每个Span。

关键追问：

- 最终回答错了，能否证明是Prompt问题？
- 查询Trace能否找到使用的索引版本？
- 大Chunk带来的Recall是否可能是虚高？

### E1

学员执行Sweep，一次只修改一个变量。重点观察：

- 大Chunk可能Recall较高，但引用和上下文效率较差；
- Query改写能解决日期格式，也可能改坏编号；
- Top-K增加会同时增加噪声、Token和延迟；
- 不能用RAGAS单一分数选型。

### E2

把7°C与5°C比较从模型迁移到规则。强调“模型提候选，专家批准，程序执行”。

## 第二天

### E3

使用相同任务压力测试Workflow、开放ReAct和有界Skill Agent。提示注入故障必须被白名单阻断。

### E4

先导入客户模拟CSV，再展示Skill渐进加载：

1. 只给模型Skill摘要；
2. 选中后读取SKILL.md；
3. 按需读取reference；
4. 只执行白名单script；
5. 将skill/version/evidence写入Trace。

最终结果必须写“候选原因未证实”。

## 第三天

### E5

比较一次性加载全部历史与按需取数。没有医学专家时，只评价规则、轨迹、证据、拒答和系统成本。

### Capstone

六组按两个相同场景配对，交换回归案例。答辩必须说明：

- 哪些步骤不交给模型；
- Skill新增时主图是否需要改变；
- 证据不足时如何停止；
- 接真实数据后还需要哪些专家标注。
